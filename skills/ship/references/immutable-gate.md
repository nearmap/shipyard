# Immutable CI and independent review

This phase is a convergence loop owned by a lightweight controller, and one dispatch of it is exactly one round. It owns the recorded build worktree; the round delegates the verdict to `sy:gate` (one verdict per review scope), disposition of that verdict's findings to `sy:gate-triage`, CI triage to `/sy:ci`, automated-review threads to `/sy:pr`, and any non-trivial fix to `sy:slice`, then applies accepted fixes, re-pushes, and re-establishes the scope. The loop converges when CI, the review verdict, and the automated reviewer's threads agree on one commit (the stopping rule in § Fix cycle); the round returns per the worker contract either way.

## Resolve gate model

Resolve once, live through the resolver (tool names resolve per `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/config-values.md`):

```
REVIEW_MODEL, REVIEW_EFFORT = the model and effort `agent_model {"name": "gate"}` reports
REVIEW_EFFORT_EXPECTED      = the effort_expected that same call reports
REVIEW_MODEL_FALLBACK       = the value `get_config {"key": "models.tiers.frontier_fallback"}` reports
```

Before resolving, compare the `fingerprint` that `fingerprint_config {}` reports against the `config_fingerprint` recorded at START. A mismatch means configuration changed mid-run: **stop and report** rather than reviewing at quietly different settings. Re-running `/sy:ship` after an intentional change is the supported path.

Pass `REVIEW_MODEL` and `REVIEW_EFFORT` as the Agent invocation's **model override** and `effort` parameter and record/reconcile them as `review_model_requested`/`review_model_observed` and `review_effort` per `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/model-dispatch.md`. On every `sy:gate` dispatch, set `review_effort_expected` to the lower of its recorded value and `REVIEW_EFFORT_EXPECTED` (low < medium < high < xhigh < max; `REVIEW_EFFORT_EXPECTED` itself when the recorded value is null), since `by_agent` pools every gate invocation's efforts. The resolver has already clamped both up to `gate`'s floor, so a config attempting a weaker reviewer never reaches here.

If a `sy:gate` invocation returns no verdict because the requested model is unavailable, re-dispatch once at `REVIEW_MODEL_FALLBACK` per model-dispatch.md's "Unavailability falls back once", set `review_model_observed` to the model that actually ran, and note the substitution in the coverage comment. If the fallback also cannot run, return `blocked` (review model unavailable) with the pinned SHAs. A model-unavailability failure must never silently promote or bounce the verdict up to the dispatcher.

## Pin scope

After push:

```text
REVIEW_BASE_SHA=<immutable merge-base/base SHA>
REVIEWED_SHA=<current PR head SHA>
TARGET_SHA=<origin/<target branch> SHA at pin time>
```

When `stacked_on_pr` is set, run **Stack rebase** (§ Fix cycle) first and use its pin; on a first scope, `REVIEW_BASE_SHA` is this layer's `base` in `gh stack view --json`. Pre-landing CI and review on the stacked head satisfy promotion and handoff.

Create a detached review worktree, under the resolved worktree root (`get_config {"key": "worktree.root"}`; defaults to the sibling directory beside the repo), pinned to `REVIEWED_SHA`. Invoke `sy:gate` there with purpose, exact SHAs, `severity_overlay_path` from state when it is non-null, `standards_reviewed_sha` and `standards_sources` from state as `STANDARDS_REVIEWED_SHA` and `STANDARDS_SOURCES` when both are non-null, and the compact design contract (plan invariants plus `accepted_deviations` from state), composing the acceptance criteria, standards authority, risk lenses, verification obligations and the plan's optional `reviewer orientation` sentence out of the plan file the state brief names — and passing that file's absolute path along with the brief rather than this phase's paraphrase of it. That costs no tracker verb and `hooks/review_guard.py` does not block it: the plan reached disk before GATE was dispatched (`${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § State router), and the guard denies mutation inside the review worktree rather than reads outside it. Add `sy:gate` to `agents_used`. Gate verifies HEAD before reviewing.

CI may run concurrently. Separate waiting from triage. Never poll `gh pr checks` or `gh run watch` once per reasoning turn, and never let a monitor self-resume at a turn-budget boundary — on a large matrix that bleeds tokens and the phase never returns. Wait with the single shared token-free background poller — launch `${CLAUDE_PLUGIN_ROOT}/scripts/ci_poll.sh poll <pr> --repo <the PR's base repository, never a fork's own origin> --head <the SHA just pushed>` with `run_in_background`; `--head` is what stops a stale or empty check set reading green, and `--allow-no-checks` is declared only for a target repo already known to have no CI; no phase hand-writes its own poller. Only once CI is terminal, delegate the diagnosis to a `/sy:ci` subagent (added to `agents_used`) that returns a compact result rather than tailing raw logs. If CI cannot reach a terminal state within a sane bound (`ci.poll_timeout`, default 1800s — raise it for repos/matrices known to run long so one poll call spans the wait), return `blocked` (CI pending) with an idempotent checkpoint and the pending run id rather than looping. Exit 3 means the PR head is not the SHA passed as `--head`: re-read it (`gh pr view <pr> --json headRefOid`) and re-establish scope on what is actually there rather than polling the old SHA again. Never apply fixes to the review checkout. If code changes, finish/cancel stale review, fix in build worktree, push, and create a new immutable review scope.

## Net-new agent-facing text

Each addition to Shipyard's own always-resident agent-facing prose justifies itself here — reviewer-initiated and builder-answerable.

- **Scope** — net-new agent-facing text in the diff: `skills/**/*.md`, `agents/*.md`, and MCP tool
  docstrings and `Field(description=...)` in `sy_tools/server.py`.
- **Carrier** — the PR body, one line per addition. Nowhere else: a justification in a commit message
  or a tracker comment does not discharge this.
- **Keep/cut test** — text stays when its reader must act on it *before* reaching the thing it
  describes and no runtime signal teaches it: an irreversible effect, a caller-declared trust boundary
  where misuse succeeds, routing between two surfaces, mutually-exclusive options. Otherwise it goes.
  Apply the two cut tests in `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/context-economy.md` by
  citation; never restate them.
- **Refutation test** — a justification survives only if removing the text would change what its
  reader does. "It adds useful background" is refuted by default. Use the refute mode `sy:hunt`
  already has. Three shapes read as cuttable and are not: a defence that stops a later reader
  simplifying a check into a no-op, a duplication `scripts/validate.py` itself requires in two places,
  and a documented carve-out.
- **Outcome** — an addition whose justification is refuted is an actionable finding in the fix cycle
  below. The builder cuts it or re-justifies there; no extra round budget, and no new `sy:gate` return
  field.

## Fix cycle

**One round per dispatch.** A dispatched worker performs exactly one pass over the current head — verdict, triage, accepted fixes, push, re-establish scope — and then returns: `done` once the stopping rule below is satisfied and it has promoted, and `handover` when it is not, carrying the same idempotent checkpoint `needs-decision` carries (`${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § Worker contract). The round bound below is what bounds the handovers; there is no second cap.

`sy:gate` reports; the round's dispositions all come from one `sy:gate-triage` delegate (at the model and effort `agent_model {"name": "gate-triage"}` reports, added to `agents_used`), seeded in its initial prompt — it holds no `SendMessage` — with the round number, the round's findings (each `sy:gate` finding under the severity group it arrived in), `severity_overlay_path` from state when it is non-null, the plan's design invariants and `accepted_deviations`, the standards contract, `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/scope-discipline.md`, and the `prior_accepts` the round's opening read returned (§ Round bound): each prior `root_cause_key` with how many rounds accepted it, so the delegate reuses a matching one rather than coining a fresh key for a cause an earlier round already keyed — a fresh key for the same cause silently defeats the recurrence check below. It returns per finding an accept with a fix spec and `ENUMERATE`, or a reject with recorded reasoning, each carrying a stable `root_cause_key`, a `SEVERITY` and an `IMPACT`. This worker applies what comes back — accepted fixes in the build worktree, then push — and authors no disposition of its own. Run each accepted fix's `ENUMERATE` command before and after the fix and put `<root_cause_key>: <before> → <after>` in the fix commit's message; a non-zero after-count is finished before the push or explained hit by hit in that message. Pass `ENUMERATE` through to any `sy:slice` dispatch. A finding whose resolution is genuinely ambiguous returns `needs-decision` (checkpoint: resolved vs pending findings and current pushed SHA); a finding exposing a plan-contract problem, or one the delegate returned tagged `ESCALATE: plan-contract`, returns `needs-decision` tagged `reason: plan_contract` rather than converging over it. A finding the delegate returned tagged `ESCALATE: owner-choice` is the owner's pick among the `OPTIONS` triage listed, not a broken plan: apply and push the round's other accepted fixes, then return one `needs-decision` tagged `reason: plan_contract_choice` carrying every such finding of the round with its options — batched, never one return per finding — and a checkpoint naming the dispositioned and still-pending findings and the current pushed SHA. Seed triage with the plan's `standards exceptions` alongside its invariants, so a finding that an excepted shape breaks the very rule the entry cites is rejected citing the entry rather than escalated. A round that returns `reason: plan_contract` or `reason: breaking_recurrence` applies none of its accepted fixes and names its dispositions file as `PENDING_FIXES`, so either ruling can carry them. A round with more than one escalation reason returns one `needs-decision` carrying every reason and its findings. A `SPLIT_REQUIRED` return means the round's findings overflowed one dispatch: re-dispatch with the same findings partitioned per the delegate's own grouping. A finding whose key an earlier round accepted is a recurrence the delegate judges (`${CLAUDE_PLUGIN_ROOT}/agents/gate-triage.md`). A non-empty `breaking_recurrences` in the round's recording `ship_gate_round` return — a breaking finding whose key two earlier rounds accepted, whatever triage's disposition — returns `needs-decision` tagged `reason: breaking_recurrence`; any other recurrence is dispositioned as triage returned it. Every new commit invalidates CI/review coverage; a fix that creates no commit (a PR-description edit, a thread reply) moves no head and opens no review scope.

**Substantive and deferrable.** A *substantive round* accepted a finding whose `IMPACT` is `breaking`, or pushed a human-thread fix; only these spend the round budget. A *deferrable* finding is an accepted finding whose `sy:gate` group is LOW and whose `IMPACT` is `non-breaking`; an `automated-reviewer` finding is deferrable on triage's `SEVERITY` LOW plus `non-breaking`.

**Terminal pass.** When the opening read reports `next_pass_terminal` (the last round accepted only non-breaking findings, pushed no human-thread fix and was not itself terminal), this pass is a terminal pass: a focused delta review over `<previous REVIEWED_SHA>..<head>`, valid under the focused-delta rule below and overriding the trivial-diff path's default full re-review, so `repo-review` never runs on it and the reviewer-findings rule below cannot fire from it. A rebase or base change in between voids it — a merge-in is one, even when the carve-out below lets a focused delta cover it — and so does a `${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § State router reconcile mismatch (a head beyond the commits the all-LOW round's own handover checkpoint accounts for): the pass is then an ordinary round with full coverage.

`sy:gate` returns `VERDICT_FILE:` and `sy:gate-triage` returns `DISPOSITIONS_FILE:`. For each, this worker names its path and never reads it — the dispositions it applies are the ones the return block carries, and recovery from either file is a human `Read`, not a loop input. A cheap-tier controller re-judging a persisted verdict by eye is the recorded fake-green shape.

**Round bound.** Each pass opens with a `ship_gate_round` call carrying neither `entry` nor `human_thread_fix`, which only reads. Its `budget` counts the substantive rounds since `gate_rounds_budget_base` against the resolved `ship.escalation.max_gate_rounds` (`${CLAUDE_PLUGIN_ROOT}/skills/shared/references/config-values.md`). At `budget.left` `0` the pass does not start: return `needs-decision` tagged `reason: max_gate_rounds`, with a checkpoint carrying the round count, the dispositioned and still-pending findings, and the current pushed SHA. A terminal pass is exempt and runs at `0`. This is the one `needs-decision` the parent never resolves itself, and only its raise-budget disposition or a planned re-entry (`${CLAUDE_PLUGIN_ROOT}/skills/ship/references/bail-reentry.md`) moves `gate_rounds_budget_base` (`${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § Worker contract).

As soon as `sy:gate`'s verdict and `sy:gate-triage`'s dispositions are in hand, before any fix dispatch or promote, the pass records itself with one `ship_gate_round` call carrying `entry` — `reviewed_sha`, verdict summary, `terminal_pass` when it is one, and per finding its `root_cause_key`, disposition (accepted, rejected, or `deferred`), `severity` (the `sy:gate` group passed to triage, or triage's grade for an `automated-reviewer` finding) and `impact` — and `phase_checkpoint`: dispositioned vs pending findings and the current pushed SHA. A trivial-diff-path pass records like any other, and a `SPLIT_REQUIRED` re-run records once, after the last partition. When the verdict's `STANDARDS_SCOPE` is `full` or `since …`, the same call passes `standards_reviewed_sha` as this pass's `REVIEWED_SHA`, so the next pass reviews conformance only where the code moved (`${CLAUDE_PLUGIN_ROOT}/agents/gate.md`); a focused-delta pass passes it only on `since …`, because its `full` covers the delta alone, and a `SPLIT_REQUIRED` re-run only when every partition was `full` or `since …`. That checkpoint is durable before the return and is the durability floor: its pushed SHA is pre-fix by construction, so the checkpoint the return carries supersedes it, and the reconcile in `${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § State router exempts exactly that lag. The round's last write is a second `ship_gate_round` carrying `human_thread_fix` (true when this round's fixes include a human-thread fix) and `next_round_causes`: every reason another pass follows, drawn from `gate-finding`, `ci-fix`, `automated-reviewer`, `human-thread`, `drift` and `rebase`, and `[]` only when the round converged, with every human thread's fix-or-reply settled first.

A `ship_gate_round` that refuses — no file at the path, a non-mapping root, or YAML that does not parse — returns `blocked` carrying the pinned SHAs, never a round treated as complete or handed over, because a round that never landed is one the cap cannot see. A non-empty `illegal` in any return is already logged by the tool; name it in the return block.

**Posting the reviewer's report.** When a pass returned a `REPO_REVIEW_REPORT` path, post that file to the pull request as one standalone comment through a `/sy:pr` delegate (added to `agents_used`) before triaging anything — `/sy:pr` owns the pull-request surface and already keeps durable evidence in comments, which is why it posts rather than the reviewer. Once per review scope: the comment names the `REVIEWED_SHA` it covers, and a re-dispatch within the same scope checks for that SHA's comment and does not post a second. A pass with no such path posts nothing, so a run whose `skills.reviewer` resolves null is unchanged. Posting is not dispositioning — the comment records what the repository's own reviewer said and what it confirmed from source, never what `sy:gate`'s refutation or this worker decided to act on, which stays entirely with the rule below. A post that fails is retried once through `/sy:pr`; still failing, return `blocked` naming the report's path in the scratch root, so the report survives on disk and the failure is visible. A report silently not posted defeats the only thing this step does.

**Reviewer findings.** A finding `sy:gate` attributes to `repo-review` (dispatched when `skills.reviewer` resolves non-null, per `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/config-values.md`) that the round declines to act on is never silently dropped: a repository's own reviewer encodes team taste rather than correctness alone, so which of its findings get thrown away is the ticket owner's call, not a cheap-tier controller's. At the end of the round return one `needs-decision` tagged `reason: reviewer_findings` carrying every reviewer finding declined in that round — batched, never one return per finding — with an idempotent checkpoint naming the dispositioned and still-pending reviewer findings and the current pushed SHA. It fires only for a round in which the reviewer actually ran, which is a full review of a new scope and never a focused delta round, so with `skills.reviewer` null it can never fire at all. Like a `max_gate_rounds` breach it is a `needs-decision` the parent never resolves itself (`${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § Worker contract); unlike one it neither increments nor rebases the two round-bound fields above, which stay that bound's alone. A rejection the user accepts is dispositioned for the stopping rule below, so accepting the round's rejections always lets the loop converge.

An accepted finding that sets a convention the repository will want next time gets the matching standards edit in the same fix round, under the rule in `${CLAUDE_PLUGIN_ROOT}/skills/ship/references/implementation.md`, so it is reviewed before convergence rather than proposed at handoff.

A finding outside the plan's declared scope is not automatically a follow-up: when it is small, adjacent, and low-risk, fold the fix into the build worktree as a recorded scope extension (added to `accepted_deviations`) rather than filing a follow-up, and batch such fold-ins into the current fix round; defer only when the fix justifies its own ticket. See `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/scope-discipline.md`.

A finding — or any direct observation in this phase — that contradicts a seeded memory anchor is authored as a `MEMORY_REFUTE` candidate in the return block and recorded to `memory_refutations` in state, never carried forward as if the anchor still held and never left to HANDOFF; the parent holds the write (see `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/memory.md`).

When `ship.request_ci_reviewer` resolves true (see `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/config-values.md`), a `/sy:pr` delegate (added to `agents_used`) requests the automated reviewer (e.g. Copilot) through `/sy:pr` §3 on the draft, before `sy:gate` is dispatched, at the start of every full-review scope: the first pass after BUILD, and any new full scope after a rebase or base change. Never request on a focused-delta round. At convergence, request once more, still on the draft, only when the diff from the reviewer's last-reviewed head — its latest review's `commit.oid`, which a `/sy:pr` delegate reads — to the current head is not trivial under § Trivial-diff cost path. When it resolves false, request nothing; human threads are reconciled the same way.

After `sy:gate` returns, a `/sy:pr` delegate (added to `agents_used`) returns the reviewer's threads and any human threads compactly, plus that `commit.oid`; `/sy:pr` §3 enumerates them by author bot-type, so trust its reconcile over an empty single-login query. The reviewer's threads join the round's `sy:gate-triage` call as `automated-reviewer` findings, and a further `/sy:pr` delegate, seeded with the returned dispositions, posts each reply. Human threads keep this worker's handling — evaluate each critically, fix the real ones in the build worktree, push back with reasoning on the rest, reply to every thread — and the nit rule never applies to them. When the scope's review has not landed by the time `sy:gate` returns, a round with accepted fixes does not wait; the next round reconciles it. A converging round waits for it, and for any convergence request, through a `/sy:pr` delegate's background review wait (`/sy:pr` §4 step 2, its wait only; whether to request is the paragraph above's alone), up to `ci.poll_timeout`. Threads that land during that wait get a second `sy:gate-triage` call in the same round, whose dispositions a second `ship_state_update` appends to that round's `gate_round_log` entry before any fix or promote; accepted fixes push, and the next round is a focused delta. A request removed or unanswered at that bound, or a could-not-review body, is recorded in the coverage comment and the round proceeds; `sy:gate` is the reviewer of record. Fixes re-establish the scope like any other; the verbose comment bodies stay out of the controller.

**Stopping rule.** The loop converges only when a pass over the current head surfaces no undispositioned actionable finding: every finding is dispositioned — accepted and fixed, `deferred`, or rejected with recorded reasoning — and what remains is at most nits triage rejected. A terminal pass converges when every finding it accepts is deferrable, and this worker defers those rather than fixing them, including any from the convergence wait's second triage. A terminal pass that accepts any non-deferrable finding, or that pushes a human-thread fix, does not converge: it fixes everything it accepted in one commit, as any round does. Deferred findings reach the PR as one comment through a `/sy:pr` delegate, each entry carrying `file:line` and its fix spec, posted in the round that defers them, after the convergence wait's second triage and before that round pushes, returns or promotes, under the reviewer's-report posting rule above: once per `REVIEWED_SHA`, the delegate added to `agents_used`, and a failed post retried once, then `blocked`. The loop never converges, promotes, or returns `done` while an undispositioned actionable finding stands (a checkpointed `blocked` return, or a `max_gate_rounds` breach, parks the loop without dispositioning them).

**Trivial-diff cost path.** When a fix round's delta is trivial — docs-only, comment-only, or `__all__`-only — the loop may skip a redundant full re-review in favour of the focused delta review below. A fix round whose `next_round_causes` is non-empty and holds only `ci-fix`, `automated-reviewer`, or both takes the focused delta too. As on any focused delta, `repo-review` does not run on it, and a rebase or base change in between voids it, as it voids a terminal pass. Cost comes out of the loop, never the reviewer: `sy:gate` still runs at the resolved frontier review model and max effort on whatever scope it reviews, coverage of the final head is never waived, and no trivial-diff path may lower those three — cost-scaling may only raise them.

**Drift re-check.** At each new review scope, and at least once per fix round, fetch the target branch and compare its head with the recorded `TARGET_SHA`. Merge it into the build branch only when `gh pr view --json mergeable,mergeStateStatus` reports `CONFLICTING` or `BEHIND`, or the user asked; otherwise note the drift and go on. After a merge-in, push, classify it as **Stack rebase** step 2 does, with the pre-merge head as old head, `TARGET_SHA` as old base and the merged target head as new base, then stamp `TARGET_SHA` to the new base. While stacked, **Stack rebase** replaces this check.

**Stack rebase.** While `stacked_on_pr` is set, at each new review scope and at least once per fix round, read the blocker PR's `state`: `CLOSED` → `bail-to-spec`. Otherwise, in the build worktree:

1. Note this layer's `base` and `head` from `gh stack view --json` as old base and old head, then run `gh stack rebase --upstack`. It replays only this layer, onto the blocker head or, once that merged, the target; the blocker branch is never rewritten. Resolve a conflict in the build worktree, `git add`, then `GIT_EDITOR=true gh stack rebase --continue`; a conflict counts as coupled. When the head moved, `gh stack push`.
2. A moved head is a new review scope against the new base, since the reviewed SHA has left the branch. Only when a prior `REV_REVIEWED_SHA` exists, classify on trees, not ancestry: compare the files in `git diff --name-only <old base> <new base>` with this ship's own, `git diff --name-only <old base> <old head>`, so fix commits pushed after the last verdict count. Disjoint, no conflict, and every file in `git diff --name-only <new base> <new head>` is in this ship's own set → focused delta, `REVIEW_BASE_SHA` = the prior `REV_REVIEWED_SHA`, `REVIEWED_SHA` = the new head. Otherwise → new full scope, `REVIEW_BASE_SHA` = the new base.
3. `TARGET_SHA` = the new base. When the blocker is `MERGED`, also `gh pr edit <pr> --base <target branch>` unless already retargeted, and stamp `stacked_on_pr: null`: the run is unstacked from then on.

A focused delta review is valid only when prior reviewed head is the immutable base and new head is immutable head. Rebase or base change requires full appropriate coverage; the one carve-out is the disjoint tree classification in **Stack rebase** step 2, which a **Drift re-check** merge-in also uses.

When current HEAD equals CI-green SHA and reviewed SHA, gate findings are resolved (including `deferred`, per the stopping rule), every existing review thread — automated reviewer (when requested) and human — is addressed, and acceptance evidence is posted, promote through `/sy:pr` and set the Task's status to `in-review` via the `tracker` skill. GATE neither requests a review at promotion nor waits for one a repository ruleset triggers on ready-for-review; `${CLAUDE_PLUGIN_ROOT}/skills/ship/references/merge-accounting.md` § Revalidate step 2 reconciles what that leaves. The tracker skill's own `validate_config`/`preflight` preamble is already discharged for this run by the parent's pre-dispatch tracker preflight (`${CLAUDE_PLUGIN_ROOT}/skills/ship/SKILL.md` § Invariants), so call `set-status` directly rather than re-running that preamble — that one verb is the whole of this worker's granted tracker access. Later human or automated review that changes code re-establishes both gates on resume.

Return `done` with coverage SHAs and `agents_used` once promoted; a round that has not reached that point returns `handover` instead.
